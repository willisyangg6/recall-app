# Retailer logo source audit

**Retrieved and verified:** 2026-09-24. **Scope:** all 77 canonical retailers in
[src/domain/retailer-catalog.ts](../src/domain/retailer-catalog.ts). **Status:** research only —
no asset was downloaded or bundled, and no code, manifest, catalog or production data changed.

This document records where an official mark exists for each canonical retailer, what the owner
says about using it, and what must be decided before any mark ships. It does not change the
rendering contract, which stays authoritative in
[docs/recall-onboarding-and-paywall.md §8](recall-onboarding-and-paywall.md#8-retailer-logos):
a mark renders only from the provenance manifest
([src/lib/retailer-logos.ts](../src/lib/retailer-logos.ts)) together with a bundled `require`
declared in [src/components/ui/retailer-logo.tsx](../src/components/ui/retailer-logo.tsx). It is
contained, never stretched, cropped or recoloured, in the fixed 40×24pt `RETAILER_LOGO_BOX`.
Otherwise the shared `home` glyph renders in the same box.

> **Not legal advice.** This is an evidence record. Whether Lotly may display any retailer's mark
> in a paid app, and on what terms, is a founder and counsel decision. Quotations are short
> excerpts kept only to show what each source says.

## 1. Executive summary

- **Catalog:** 77 entries, confirmed against the source. `RETAILER_LOGO_MANIFEST` and `MARKS` are
  both empty, so all 77 render the `home` fallback today (`retailerLogoCoverage()`;
  [retailer-logos.test.ts](../src/lib/retailer-logos.test.ts) pins the count).
- **Tiers:** **A 0 · B 64 · C 13.** None of the 77 official sources grants app or commercial use.
  Every usage statement found falls into one of four kinds: media or editorial use only, personal
  and non-commercial use only, existing vendors only, or prior written consent required. So the
  exact official mark is usually easy to find, but permission to use it never is.
- **Operating status (as of 2026-09-24):**
  - 76 banners are current and 1 is defunct: **Owen's**, converted to Kroger in August 2020.
  - 5 changed ownership and still operate: Family Dollar, Winn-Dixie, The Fresh Market, FoodMaxx
    and Lucky.
  - 2 are pending acquisition: Giant Eagle and Market District (Kroger, expected to close in 2027).
  - No storefront banner was renamed. Three refreshed their marks recently: Walmart (2025),
    Winn-Dixie (January 2026) and Sam's Club (from 2026-05-28, still rolling out).
- **Major blockers:**
  1. **Permission.** Not one source licenses app use, so every mark needs written permission.
  2. **Unverified marks.** 13 retailers are Tier C. Owen's is defunct and Price Chopper is
     ambiguous. The other 11 have no exact mark verified, mostly because their official sites
     blocked automated access. Every Kroger banner site also timed out; the Kroger evidence comes
     from Kroger's own asset library instead.
  3. **Legibility.** Four Kroger-family marks are wider than 5:1 and would be about 6–8pt tall in
     the box.
  4. **Identity ambiguity.** Price Chopper names two unrelated chains, Kwik Trip also trades as
     Kwik Star, and the GIANT (PA) storefront mark was not found.
- **Recommended rollout:** keep the current house fallback and add official marks in coherent,
  permission-backed batches — option 2 in §6. This is a founder decision. The request that unlocks
  the most is one written request to Kroger: Kroger's own library already holds exact current
  files for all 19 live Kroger banners.
- **Decisions this audit cannot make:** listed in
  [Founder and counsel decisions](#founder-and-counsel-decisions).

## 2. Audit table

Every catalog id appears exactly once, in catalog order.

**Tier definitions:**

- **A:** an official source offers the exact mark with terms clear enough to justify founder
  review for bundling.
- **B:** the exact current mark is on an official source, but app use is not permitted or not
  addressed.
- **C:** no exact current mark was verified from an official source, the banner is defunct, or
  the identity is ambiguous.

**How to read the columns:**

- "Official source URL" is the page that was opened and inspected. For a Tier C row it explains
  what was tried.
- A "header" source means the mark appears in the retailer's own site header; the note gives the
  file name or alt text found in the page markup.
- No image or asset file was downloaded or opened. Mark type and variants therefore come from file
  names and page listings, and "not inspected" means exactly that.
- Recommended filenames follow the existing `assets/retailer-logos/<id>.png` (+ `@2x`, `@3x`)
  contract.

recall notices name banners and people shop at banners, and the same rule governs marks: a parent's
corporate mark, a sister banner's mark, or a shared symbol cropped out of a lockup is never an
acceptable stand-in.

## 5. Proposed asset contract

This is a recommendation, not an implementation. It extends the existing contract and does not
replace it. The repository precedents it follows are the vendored Lucide sources beside
[scripts/render-onboarding-assets.mjs](../scripts/render-onboarding-assets.mjs), and the sha256 and
sRGB pins in [src/lib/allergen-assets.test.ts](../src/lib/allergen-assets.test.ts) and
[src/lib/mascot-assets.test.ts](../src/lib/mascot-assets.test.ts).

- **Directories.**
  - Shipped rasters stay where the existing test expects them:
    `assets/retailer-logos/<id>.png`, `<id>@2x.png`, `<id>@3x.png`.
  - The owner's original file is vendored as source only, never `require`d, at
    `assets/retailer-logo-sources/<id>.<ext>`. Written permission is recorded beside the manifest
    entry and never committed as a secret or personal email.
- **Filenames.** Keyed to the canonical id only (`fred-meyer.png`), never the owner's file name.
  One mark per id.
- **Accepted source types.** SVG, AI, EPS or PDF vectors, or a PNG at least 3× the rendered size,
  in RGB or sRGB.
  - A CMYK-only file (BJ's, Hannaford, Food Lion) is not accepted. Converting it is a colour change
    the owner has not approved, so request an RGB file.
  - JPEG is not accepted, because it has no transparency.
- **SVG stays source-only; generated PNGs ship.** React Native `Image` does not render SVG, and
  `react-native-svg` would make the owner's vector executable layout code in the app. An offline,
  deterministic renderer (`scripts/render-retailer-logos.mjs`, the same pattern as the onboarding
  renderer) rasterises each source.
- **Raster dimensions.** Fit the artwork's own bounds inside 40×24pt, preserving its ratio. One
  dimension then equals the box (40pt or 24pt) and the other is at most the box. That gives at
  most 40×24 px at 1x, 80×48 at 2x and 120×72 at 3x. `width`/`height` in the manifest are the 1x
  pixel size, as today.
- **Aspect ratio and legibility.**
  - Preserve the ratio exactly, and keep any clear space the owner's guidelines require.
  - Proposed gate: a contained mark must be at least **8pt tall**, which means a ratio of 5:1 or
    narrower. Below that, use an owner-supplied compact or icon variant, or keep the fallback.
  - On file metadata this fails Pick 'n Save (~7.1:1), Harris Teeter (~6.4:1), Fred Meyer
    (~6.0:1) and Food 4 Less (~5.3:1).
  - Confirm the threshold visually before adopting it.
- **Transparency and colour.**
  - 8-bit RGBA PNG, tagged sRGB, with a transparent background.
  - Transparent pixels hold no hidden colour, and there is no background or timestamp chunk: the
    same mechanical rules as the mascot set.
  - The app is light-only (`userInterfaceStyle: "light"`, dark mode deferred in
    [DESIGN.md](../DESIGN.md)), so ship the owner's primary light-background variant. A reversed
    variant is recorded but not shipped until dark mode exists.
  - A "light" header file meant for dark backgrounds (Market District) needs its counterpart.
- **Additional manifest fields** (beyond `retailerId`, `sourceUrl`, `owner`, `retrievedOn`,
  `permission`, `width`, `height`):
  - `sourceFile`: repo path of the vendored original.
  - `sourceSha256`: fingerprint of the original as retrieved.
  - `generatedSha256`: one fingerprint per shipped scale.
  - `variant`: `primary` | `compact` | `icon`.
  - `permissionRef`: the dated written permission, e.g. "email from <owner> comms, 2026-10-02".
  - `permissionScope`: exactly what was granted.
  - `storefrontVerifiedOn`: when someone compared the file with current signage.
  - `recheckAfter`: set for banners in flux (Winn-Dixie, Sam's Club, Family Dollar, Giant Eagle,
    Lucky).
- **Prohibitions** (already enforced in part by
  [retailer-logos.test.ts](../src/lib/retailer-logos.test.ts)):
  - no recolouring (no `tintColor`), cropping, stretching or effects;
  - no hotlinking or runtime fetch;
  - no logo services or favicons;
  - no screenshots, tracing or AI recreation;
  - no parent or sister-banner substitution;
  - no historical marks.
- **Accessibility (unchanged).**
  - The mark is decorative, and the row speaks the retailer name from its own label.
  - The box carries the name as `accessibilityLabel` whether it shows a mark or the fallback.
  - Nothing is conveyed only by the mark, and a mark is never the sole identification of a store.
- **Testing the 40×24pt box.** Extend
  [retailer-logos.test.ts](../src/lib/retailer-logos.test.ts) so that:
  - every manifest entry has `@1x`/`@2x`/`@3x` files at exactly 1:2:3 pixel ratios;
  - the 1x file fits 40×24 with one side flush, and the manifest `width`/`height` equal the 1x
    file;
  - every file is 8-bit RGBA, sRGB-tagged and hash-pinned, and the source hash matches the
    vendored original;
  - the contained height meets the legibility gate.

  Then render every shipped mark in the Design Preview's retailer rows beside the fallback.
  Screenshots prove rendering only.

## 6. Visual coverage strategy

**Option 1: release only when all 77 have official marks.**

- Consistency: perfect.
- Comprehension: good.
- Trademark risk: highest total exposure, because it requires 77 grants.
- Complexity: low per mark, but the release never happens. Owen's has no current mark, 13 entries
  are Tier C, and each Tier B entry needs its own grant.

**Option 2: mix official marks with the current house fallback.**

- Consistency: mixed. Colour marks sit beside a grey `home` glyph.
- Comprehension: good. The glyph already reads as "a store", and rows stay one height.
- Trademark risk: scales with exactly what has been granted.
- Complexity: lowest. The contract, tests and component already exist, and each approved entry is
  one manifest row plus three files.
- Main downside: a few colourful marks can make unmarked stores look second-class, or seem to
  single out partners.

**Option 3: mix official marks with a new neutral monogram fallback.**

- Consistency: better at a glance.
- Comprehension: worse. A letter tile reads as a logo: "W", "T" or "K" in a circle can look like a
  real mark. Many retailers share initials (ten "S", eight "F", seven "W"), and monograms add visual noise
  to a 77-row list.
- Trademark risk: a generated monogram can be mistaken for the owner's mark.
- Complexity: medium. It needs a new design and a new fallback contract, and it changes the
  documented `home` rule.

**Option 4: official marks only in a "Popular retailers" section; the full list stays neutral.**

- Consistency: good within each section.
- Comprehension: good for the shortlist.
- Trademark risk: concentrated in a few grants.
- Complexity: highest. It redesigns Retailers (a new section, ordering and search behaviour), and
  "popular" needs evidence Lotly does not have. A duplicated row could also show one store checked
  in two places.

**Recommendation (founder decision): option 2, released in coherent batches rather than one mark
at a time.** Ship a batch only when a meaningful set is approved together, for example the whole
Kroger family or the first-wave nationals. Keep the `home` glyph for everything else. This keeps
the existing contract, needs no redesign, and scales trademark exposure exactly with permission in
hand. Staying all-neutral (today's state) remains a legitimate outcome if permission is not
obtained.
